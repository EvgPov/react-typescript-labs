Тонкая настройка - это умение понимать и контролировать жизненное поведение интерфейса.
Когда в компоненте меняется состояние, React:
	- повторно вызывает функцию компонента
	- получает новый JSX
	- строит новое виртуальные представление интерфейса
	- сравнивает его с предыдущим
	- вычисляет, что именно изменилось
	- только после этого обновляет реальный DOM
Этот процесс состоит из двух важный идей:
	- компонент в React - это функция, которая получает входные данные и возвращает описание интерфейса.
React не хранит сам JSX как "живой HTML". JSX - это просто описание того, что должно быть нарисовано.
	- React использует виртуальные представление интерфейса в памяти. Это не настоящий DOM браузера, а его абстракция.
Условно можно мыслить так:
	- до изменения состояния React помнит старую версию интерфейса
	- после изменения состояния он создает новую версию
	- затем сравнивает старую и новую версии
	- обновляет только то, что реально изменилось
Надо научиться различать:
	- полезный рендер - когда интерфейс реально изменился
	- лишний рендер - когда компонент обновился, хотя визуально и логически ничего важного не произошло.

Компонент может ререндерится по нескольким причинам:
	- изменился его state
	 Когда вызывается setCount, React планирует обновление компонента

	- изменились его props
	Если родительский компонент передал новые данные, дочерний компонент тоже перерисуется.
	
	- перерисовал родитель
	Даже если props визуально "такие же", дочерний компонент по умолчанию все равно будет вызван заново вместе с родителем.

React по умолчанию заново выполняет дерево компонентов ниже того места, где произошло событие.


React.memo позволяет React запомнить результат компонента и повторно использовать его, если props не изменились.
React.memo делает поверхностное сравнение props:
 	- был ли раньше тот же примитив
	- была ли раньше та же ссылка на объект или массив
	- была ли раньше та же ссылка на функцию

Объекты и массивы
	При каждом рендере создается новый объект. Даже если внутри он выглядит одинаково, для JavaScript это уже другая ссылка. Из-за этого React.memo в таких случаях может не помочь.
Функции
	При каждом рендере создается новая функция. Для React это новый prop.

Поэтому если мы активно используем мемоизацию, приходится внимательнее относится к объектам и функциям.


SyntheticEvent - это объект события, который создает React поверх наливного DOM-события браузера.

<button onClick={handleClick}>Нажми</button>
В обработчик приходит не "сырая" браузерная структура, а React-объект, который:
	- ведет себя одинаково в разных браузерах
	- имеет единый интерфейс
	- поддерживает привычные методы вроде preventDefault и stopPropagation

React сделал свою систему событий потому что:
	- Единое поведение
	Разработчик работает через од н и тот же интерфейс, не думая о различия в браузерах
	- удобная интеграция с React
	События в React встроены в его модель обновление и жизненный цикл
	- централизованная обработка
	React умеет эффективно организовывать подписки через делегирование событий

Когда пользователь кликает на кнопку, происходит такая цепочка:
	- браузер создает нативно DOM-событие
	- React получает это событие
	- React создает объект SyntheticEvent
	- React вызывает нужный обработчик
	- если обработчик меняет state, React запускает новый рендер

React не обязан решать отдельный реальный браузерный обработчик на каждый элемент. Вместо этого используется идея делегирования событий.
Событие происходит на вложенном элементе, но браузер может "поднять" его вверх по DOM-дереву. Можно повесить меньшее количество обработчиков выше, а потом определять, где именно событие произошло.
React строить свою систему событий вокруг такой централизованной модели.
Это даёт:
	- меньше прямых подписок
	- более удобное управление
	- предсказуемую интеграцию с React

function Button() {
  function handleClick(event) {
    console.log(event);
    console.log(event.type);
    console.log(event.target);
  }

  return <button onClick={handleClick}>Нажми</button>;
}

	- handleClick передается в onClick
	- когда пользователь кликает, React вызывает handleClick
	- в параметр event попадает объект события
	- через него можно получить тип события, элемент-источник и другие данные

event.target: Элемент, на котором произошло событие фактически (куда реально кликнули)

event.currentTarget: Элемент, на котором выполняется обработчик (куда повесили onClick)

target — меняется в зависимости от того, по какому дочернему элементу кликнули
currentTarget — всегда один и тот же (элемент с обработчиком)
Это работает благодаря всплытию событий: событие возникает на самом глубоком элементе (target), затем поднимается вверх по дереву, и currentTarget на каждом уровне — это текущий элемент, где выполняется обработчик.

target — цель (куда попали)
currentTarget — текущий слушатель (кто слушает)

target = кто реально получил удар
currentTarget = кто стоит с радаром и его ловит

Метод preventDefault() отменяет стандартное поведение браузера

Что произошло бы без preventDefault
Браузер попытался бы отправить форму стандартным способом и перезагрузить страницу.

Что происходит с preventDefault
Мы берём управление в свои руки и сами решаем, что делать при отправке формы.

Метод stopPropagation() останавливает всплытие события вверх
Это нужно, когда событие не должно дойти до родительских обработчиков.

В React события передаются как props в camelCase

<button onClick={handleClick}>Click</button>

React -- это не HTML-шаблонизатор, а JavaScript-описание интерфейса. Потому обработчик - это не строка, а функция. Мы передаем ссылку на функцию. 

<button onClick={handleClick}>Нажми</button>
Здесь React сохранит функцию и вызовет ее позже, когда произойдет событие.

<button onClick={handleClick()}>Нажми</button>
Здесь функция вызовется сразу во время рендера, а не при клике. 

<button onClick={() => deleteUser(id)}>Удалить</button>

Если нужно передать аргументы в обработчик, то надо использовать стрелочную функцию.

Событие и аргумент одновременно:

function handleDelete(id, event) {
  console.log(id);
  console.log(event.type);
}

<button onClick={(event) => handleDelete(user.id, event)}>
  Удалить
</button>

В React onChange в полях формы обычно используется как основной способ отслеживать ввод пользователя


import { useState } from 'react';

function InputExample() {
  const [value, setValue] = useState('');

  function handleChange(event) {
    setValue(event.target.value);
  }

  return <input value={value} onChange={handleChange} />;
}

	- поле отображает значение из state
	- пользовать вводит символ
	- React получает событие
	- из event.target.value берется новое значение
	- вызывается setValue
	- компонент перерисовывает
	- новое значение снова попадает в value

Кода нужен прямой доступ к DOM
	- поставить фокус на поле
	- прокрутить страницу до элемента
	- измерить размеры блока
	- вызвать методы DOM-элемента
	- подключить внешнюю библиотеку, которая работает напрямую с DOM.

ref - это специальный объект, который React может связать с DOM-элементом или другим значением.

С useRef мы создаем объект вида: {current: ...}
Свойство current хранит текущее значение

State
	- хранит данные для интерфейса
	- изменение state вызывает рендер
	- используется для того, что должно быть видно в JSX
Ref
	- хранит значние между ренлерами
	- изменение ref не вызывает рендер
	- используется для доступа к DOM или хранения служебных значений


import { useRef } from 'react';

function InputFocus() {
  const inputRef = useRef(null);

  function handleFocus() {
    inputRef.current.focus();
  }

  return (
    <div>
      <input ref={inputRef} />
      <button onClick={handleFocus}>Фокус</button>
    </div>
  );
}


	- useRef(null) создает объект {current: null}
	- React связывает ref={inputRef} и DOM- элементом <input>
	- после рендера в inputRef.current попадает реальный DOM imput
	- при нажатии кнопки вызывается focus()
	- после получает фокус

ref не вызывает ререндер, потому что React не отслеживает ref.curent как часть реактивного интерфейса. Это просто объект, в котором мы можем хранить значения между рендерами.

Когда хранить значные в ref, а когда в state

В state:
	- значение влияет на UI
	- пользователь должен увидеть его на экране
	- интерфейс зависит от этого значения
В ref:
	- это служебное значение
	- оно не должно вызывать обновление
	- нужен доступ к DOM
	- нужно запомнить что-то между рендерами


Порталы

Обычно React-компоненты рендерятся внутрь общего корня приложения и DOM повторяет структуру компонентов.
Есть компоненты, которые логически принадлежат одному месте приложения, но визуально должны быть показаны совсем в другом месте DOM.
Родительские контейнеры могут иметь ограниченную область, собственный z-index, позиционирование, мешающее всплывающему элементу. В итоге модальное окно, которое должно лежать поверх всего экрана, оказывается "зажатым" внутри родителя.

Портал - это способ отрисовать React-компонент в другой DOM-узел, не разрывая его связь с React-деревом.
То есть:
	- логически компонент остается частью текущего React-приложения
	- но физически в DOM он вставляется в другое место
Логически
Modal  вызывается внутри App
Для React это обычный дочерний компонент

Физически в DOM
Содержимое мочалки вставляется не внутрь DOM-узла App, а в #modal-root

Портал удобен для модалок, потому-что модалке нужно:
	- перекрыть весь экран
	- не зависеть от верстки страницы
	- лежать поверх всех блоков
	- легко управлялся через одно состояние isOpen

Даже если DOM-узел физически находится в другом месте, React все равно сохраняет связь с React-деревом. 
То есть с точки зрения React этот компонент продолжает жить внутри той же структуры компонентов.
Это значит, что портал - это не "отдельное приложение" и не "вне React". Это просто другой DOM-вывод.

Higher-Order Component: Компоненты высшего порядка

Функция высшего порядка - это функция, которая:
	- принимает другую функцию
	- и/или возвращает другую функцию

Higher-Order Component - это функция, которая принимает компонент и возвращает новый компонент.

HOC(Component) => NewComponent

То есть HOC не рисует UI сам по себе как обычный компонент.
Он берет существующий компонент и добавляет ему новое поведение.

Главная цель HOC - переиспользование логики.

Пусть у нас есть несколько компонентов и всем нужно:
	- логировать рендер
	- проверять доступ пользователя
	- показывать loader
	- оборачивать в рамку
	- подмешивать дополнительные props
Если писать вручную в каждом компоненте, то код начнет дублироваться
HOC позволяет нести такую логику в отдельную функцию-обертку
HOC 
	- не изменяет исходный компонент
	- не переписывает его код
	- просто создает новый компонент, который использует старый внутри себя
Это композиция, а не мутация
HOC хорошо показывает важную идею React:
	поведение можно не копировать, а переиспользовать через композицию
HOC - это способ добавлять компонентам повторно используемое поведение через обертку
