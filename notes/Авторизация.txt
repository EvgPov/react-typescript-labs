Аутентификации - это проекрка личности.
Авторизация - это проверка прав.

На практике в интерфейсах эти процессы идут вместе: сначала узнаем кто это, потом решаем куда его пустить. Поэтому когда говорят "добавь авторизацию" - обычно имеют в виду оба сценария.

Что происходит при открытии приложения:
	- приложение запустилось - пользователь пока неизвестен
	- пользователь может ввести свои данные и войти
	- после входа приложение должно где-то запомнить, что он вошел
	- если пользователь обновил страницу - приложение должно восстановить его данные
	- некоторые страницы должны быть закрыты для тех, кто не вошел
	- когда пользователь нажимает "Выйти" - все должно очиститься
	
Пользователь в React-приложении - это просто объект с полями. Если объект есть в состоянии - пользователь авторизован, если его нет - пользователь не авторизован.

user === null - пользователь не авторизован
user !== null - пользователь не авторизован

Поле role связывает факт автори нации с правами доступа.
Два разных пользователя с одинаковым фактом авторизации видят разный интерфейс.

localStorage - это хранилище в браузере, которое работает по принципу "ключ-значение". Данные в нем остаются даже после закрытия вкладки и перезагрузки страницы. Они удаляются только если пользователь сам очистит данные сайта или вызовом removeItem.
	- записать значение localStorage.setItem('ключ', 'знчание')
	- прочитать значение localStorage.getItem('ключ')
	- удалить знчание localStorage.removeItem('ключ')

localStorage.setItem('auth_user', JSON.stringify(user)) - сохранение объекта в localStorage
JSON.parse(localStorage.getItem('auth_user')) - восстановление объекта из localStorage

BrowsetRouter - это компонент, который использует History API для синхронизации React-приложения с текущим URL в адресной строке браузера.

BrowsetRouter стоит снаружи AuthProvider, потому что внутри AuthProvider нам могу понадобится хуки Router.

AuthProvider обрачивает App - это означает, что весь интерфейс приложения имеет доступ к данным пользователя через контекст.
Любой компонент, вызывающий useAuth()точно знает, что получит: объект пользователя, флаг проверки, функцию входа и функцию выхода.

NavLink наследуется от Link, но добавляет возможность определить, совпадает ли текущий URL с to.

<NavLink to="/profile">Профиль</NavLink>

ПО умолчанию, когда вы на странице  /profile, к этой ссылке автоматически добавляется класс active.

По умолчанию NavLink использует префиксное сравнение:

// Ссылка активна на ВСЕХ путях, начинающихся с /courses
<NavLink to="/courses">Курсы</NavLink>
// Активна: /courses, /courses/manage, /courses/123/edit

Чтобы точное совпадение, добавьте end:

<NavLink to="/courses" end>Курсы</NavLink>
// Активна ТОЛЬКО на /courses
// На /courses/manage — уже не активна


NavLink = Link + отслеживание текущего URL
