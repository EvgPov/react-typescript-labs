1. Классовый компонент
Классовый компонент - это ES6-класс (это обычный JavaScript-класс, написанный с использованием синтаксиса ES6 (class ... extends ...)), наследующий от React.Component. Чтобы класс стал компонентом React, он обязательно должен наследовать от React-Component. Именно от этого базового класса Reactберет все необходимые методы и свойства, чтобы класс можно было использовать как компонент: render(), this.props, this.state, методы жизненного цикла componentDidMount, componentDidUpdate, shouldComponentUpdate и т. д.

Классовый компонент - это обычный JS-класс, который написан с ключевым словом class, наследуется от React.Component или React.PureComponent, обязательно имеет метод render(), который возвращает JSX (или null), может иметь состояние (this.state), методы жизненного цикла, this.props.

props -  только для чтения, компонент не должен их мутировать
state - приватные данные, изменяются только через this.setState
this.setState асинхронный и может принимать callback-функцию
Методы класса нужно биндить (стрелочные функции или bind в конструкторе), иначе this потеряется в обработки.
Стрелочные функции не имеют собственного this, они берут this из окружающего лексического контекста (в данном случае — экземпляра класса). 
В классовых компонентах обычные методы теряют this, когда их передают как колбэки (onClick, setTimeout и т.д.).
Метод bind - это способ явно привязать значение this к функции, чтобы оно не терялось при передаче функции как callback.

Основные фазы жизненного цикла:
- Mounting - компонент создается и вставляется в DOM
- Updating - компонент перерисовывается из-за изменения props или state
- Unmounting - компонент удаляется из DOM

Основные методы жизненного цикла

componentDidMount - запускается один раз сразу после первого рендера и вставки в DOM.
- загрузка данных
- подписка на внешние события (механизм получения реальных данных в реальном времени от сервера без необходимости постоянно обновлять страницу или делать повторяющие запросы)
- запуск таймеров/анимаций

componentDidUpdate(prevProps, prevState, snapshot?)
Запускается после каждого обновления (кроме первого рендера).
Важно сравнивать предыдущие значения и текущие, чтобы не делать лишнюю работу.

componentWillUnmount
Запускается прямо перед удалением компонента из DOM.
Критически важно для очистки ресурсов:
- clearInterval / clearTimeout
- Отписка от WebSocket / EventEmitter
- Удаление глобальных слушателей событий


MOUNTING
Классовый метод:  componentDidMount
Эквивалент в хуках: useEffect(() => {
1. Выполняется ПОСЛЕ того, как React обновил DOM
2. Выполняется только на КЛИЕНТЕ (не на сервере)
3. При пустом массиве [] — выполняется 1 раз
}, []) Пустой массив = нет зависимостей = эффект не перезапускается

/ Порядок выполнения:

// 2. React обновляет DOM
// 3. 🟢 useEffect выполняется (componentDidMount)
// 4. Компонент живет...
// 5. 🔴 При размонтировании: функция очистки (componentWillUnmount)


UPDATING
Классовый метод:  componentDidUpdate
Эквивалент в хуках: useEffect(() => {}, [deps]) - конкретные зависимости
useEffect(fn) (без массива) - все зависимости


UNMOUNTING
Классовый метод:  componentWillUnmount
Эквивалент в хуках: cleanup-функция внутри useEffect

useEffect(() => { return cleanup }, [])

componentDidMount + DidUpdate -> useEffect(() => { ... }, [deps]) (без cleanup)


useEffect - это хук, который позволяет выполнять побочные эффекты в функциональных компонентах. Он заменяет методы жизненного цикла классовых компонентов: componentDidMount, componentDidUpdate, componentWillUnmount.

- Оптимизация: React может пропустить перерисовал, если входные данные не изменились.

Тяжелый компонент - это компонент, чей рендер (или монтирование) занимает заметное время и/или ресурсы. Признаки: большое количество DOM-узлов (длинный текст таблица 100*50), сложные вычисления прямо в render (фильтрация/сортировка 10000 элементов), тяжелые сторонние библиотеки (график, видео-плеер), анимации/canvas. Главный критерий: если удаление/добавление этого компонента заметно влияет на плавность интерфейса при изменении состоянии выше по дереву -> он тяжелый.

React.memo - это высокоуровневая функция-обертка, которая позволяет мемоировать (кешировать) результат рендера функционального компонента и предотвращать его повторный рендер, если пропсы не изменились (если у компонента те же пропсы, что и в прошлый раз - не рендери его заново, просто верни предыдущий результат).
React сравнивает предыдущие проемы и текущие пропсы с помощью поверхностного сравнения:
- если все пропсы те же самые, то возвращает предыдущий результат рендера (не вызывает функцию компонента)
- если хотя бы один про изменился, то вызывает функцию заново.

Почему важно логировать ошибки

Отладка — понимаете, что пошло не так
Мониторинг — можно настроить оповещения об ошибках
Аудит — запись всех проблем для последующего анализа
Поддержка — легче воспроизвести и исправить баги

static getDerivedStateFromError() — метод жизненного цикла React для обработки ошибок

Это статический метод в React-компонентах, который вызывается, когда в дочернем компоненте происходит ошибка. Он позволяет обновить состояние компонента-перехватчика ошибок (Error Boundary).

Как это работает

javascript
static getDerivedStateFromError(error) {
  // Вызывается после ошибки в дочернем компоненте
  // Получает ошибку как параметр
  // Должен вернуть объект для обновления состояния
  return { hasError: true, error };
}
Полный пример Error Boundary

javascript
import React, { Component } from 'react';

class ErrorBoundary extends Component {
  constructor(props) {
    super(props);
    this.state = {
      hasError: false,
      error: null,
      errorInfo: null
    };
  }

  // 1. СНАЧАЛА вызывается этот метод
  static getDerivedStateFromError(error) {
    // Обновляем состояние, чтобы показать fallback UI
    console.log('1. getDerivedStateFromError поймал ошибку:', error);
    
    return {
      hasError: true,  // показываем, что ошибка произошла
      error: error     // сохраняем ошибку для отображения
    };
  }

  // 2. ПОТОМ вызывается componentDidCatch (если есть)
  componentDidCatch(error, errorInfo) {
    // Здесь можно отправить ошибку в сервис логирования
    console.log('2. componentDidCatch отправил ошибку в лог:', error, errorInfo);
    
    // Отправляем в Sentry / LogRocket / свой сервис
    logErrorToService(error, errorInfo);
  }

  render() {
    // 3. ИСПОЛЬЗУЕМ обновленное состояние для рендера
    if (this.state.hasError) {
      // Показываем запасной UI
      return (
        <div className="error-boundary-fallback">
          <h2>Что-то пошло не так</h2>
          <details>
            <summary>Детали ошибки</summary>
            <p>{this.state.error?.toString()}</p>
          </details>
          <button onClick={() => window.location.reload()}>
            Обновить страницу
          </button>
        </div>
      );
    }

    // Если ошибки нет, рендерим дочерние компоненты
    return this.props.children;
  }
}

// Использование
function App() {
  return (
    <ErrorBoundary>
      <MyComponent />
    </ErrorBoundary>
  );
}

class AdvancedErrorBoundary extends Component {
  state = {
    hasError: false,
    error: null,
    errorType: null
  };

  static getDerivedStateFromError(error) {
    // Определяем тип ошибки для разного отображения
    let errorType = 'unknown';
    
    if (error instanceof TypeError) {
      errorType = 'type';
    } else if (error instanceof ReferenceError) {
      errorType = 'reference';
    } else if (error.message.includes('network')) {
      errorType = 'network';
    } else if (error.message.includes('auth')) {
      errorType = 'auth';
    }
    
    // Сохраняем информацию об ошибке
    return {
      hasError: true,
      error: error,
      errorType: errorType,
      timestamp: new Date().toISOString()
    };
  }

  componentDidCatch(error, errorInfo) {
    // Логируем с дополнительной информацией
    console.group('Error Boundary Catch');
    console.log('Тип ошибки:', this.state.errorType);
    console.log('Ошибка:', error);
    console.log('Компонент:', errorInfo.componentStack);
    console.groupEnd();

    fetch('/api/log-error', {
      method: 'POST',
      body: JSON.stringify({
        error: error.toString(),
        type: this.state.errorType,
        stack: error.stack,
        componentStack: errorInfo.componentStack,
        timestamp: this.state.timestamp,
        url: window.location.href,
        userAgent: navigator.userAgent
      })
    });
  }

  getErrorMessage() {
    const { errorType, error } = this.state;
    
    const messages = {
      type: 'Произошла ошибка типов данных',

      unknown: error?.message || 'Неизвестная ошибка'
    };

  }

Комбинация с разными fallback UI

javascript
class ErrorBoundary extends Component {
  state = { hasError: false, error: null };

  static getDerivedStateFromError(error) {
    return { hasError: true, error };
  }

  render() {
    if (this.state.hasError) {
      // Можно использовать разные fallback в зависимости от props
      if (this.props.fallback) {
        return this.props.fallback;
      }
      
      // Или кастомный компонент ошибки
      if (this.props.FallbackComponent) {
        return <this.props.FallbackComponent error={this.state.error} />;
      }
      
      // Или функцию, которая возвращает UI
      if (typeof this.props.fallbackRender === 'function') {
        return this.props.fallbackRender({ error: this.state.error });
      }
      
      // По умолчанию
      return <DefaultFallback error={this.state.error} />;
    }

    return this.props.children;
  }
}

Статические методы в классах JavaScript/TypeScript

Статические методы — это методы, которые принадлежат самому классу, а не его экземплярам. Они вызываются через класс, а не через объекты, созданные от этого класса.

Базовый синтаксис

javascript
class MyClass {
  static myMethod() {
    console.log('Это статический метод');
  }
  
  regularMethod() {
    console.log('Это обычный метод');
  }
}

// Вызов статического метода
MyClass.myMethod(); // ✅ "Это статический метод"

// ❌ Нельзя вызвать через экземпляр
const obj = new MyClass();
obj.myMethod(); // Ошибка! obj.myMethod is not a function

// Обычный метод можно вызвать только через экземпляр
obj.regularMethod(); // ✅ "Это обычный метод"
MyClass.regularMethod(); // Ошибка!

      available: DatabaseConnection.#maxConnections - DatabaseConnection.#instanceCount

      DatabaseConnection.#instanceCount--;
      this.connected = false;
      console.log(`Подключение #${this.id} закрыто`);
    }
  }

  static validateForm(data, validationRules) {
    const errors = {};
    
    for (const [field, rules] of Object.entries(validationRules)) {
      const value = data[field];
      
      if (rules.required && !Validator.validateRequired(value)) {
        errors[field] = 'Поле обязательно';
        continue;
      }
      
      if (rules.email && !Validator.validateEmail(value)) {
        errors[field] = 'Некорректный email';
      }
      
      if (rules.minLength && value.length < rules.minLength) {
        errors[field] = `Минимум ${rules.minLength} символов`;
      }
      
      if (rules.maxLength && value.length > rules.maxLength) {
        errors[field] = `Максимум ${rules.maxLength} символов`;
      }
    }
    
    return {
      isValid: Object.keys(errors).length === 0,
      errors
    };
  }
}

Полный рабочий пример

typescript
import React from 'react';

// Определяем типы
interface Props {
  children: React.ReactNode;      // что оборачиваем
  fallback?: React.ReactNode;      // запасной UI (опционально)
  onError?: (error: Error, errorInfo: React.ErrorInfo) => void; // колбэк при ошибке
}

interface State {
  hasError: boolean;  // была ли ошибка
  error: Error | null; // информация об ошибке
}

// Класс-перехватчик ошибок
export class SimpleErrorBoundary extends React.Component<Props, State> {
  // Инициализация состояния с типизацией
  state: State = {
    hasError: false,
    error: null,
  };

  // Статический метод - вызывается при ошибке
  static getDerivedStateFromError(error: Error): Partial<State> {
    // Обновляем состояние, чтобы показать fallback UI
    return {
      hasError: true,
      error: error
    };
  }

  // Вызывается после ошибки (для логирования)
  componentDidCatch(error: Error, errorInfo: React.ErrorInfo) {
    // Вызываем колбэк, если передан
    if (this.props.onError) {
      this.props.onError(error, errorInfo);
    }
    
    // Логируем ошибку
    console.error('Поймана ошибка:', error, errorInfo);
  }

  // Сброс ошибки (например, при повторной попытке)
  resetError = () => {
    this.setState({
      hasError: false,
      error: null
    });
  };

  render() {
    // Если есть ошибка - показываем fallback UI
    if (this.state.hasError) {
      // Если передан кастомный fallback - используем его
      if (this.props.fallback) {
        return this.props.fallback;
      }
      
      // Иначе показываем стандартный fallback
      return (
        <div className="error-boundary-fallback">
          <h2>Что-то пошло не так</h2>
          <details>
            <summary>Детали ошибки</summary>
            <p>{this.state.error?.toString()}</p>
          </details>
          <button onClick={this.resetError}>
            Попробовать снова
          </button>
        </div>
      );
    }

    // Если ошибки нет - рендерим дочерние компоненты
    return this.props.children;
  }
}

error boundary переведи в контексте программирования
Error Boundary — что это в программировании?

Error Boundary (читается как "Эррор Баундари") — это компонент-перехватчик ошибок или граница ошибок. Это механизм в React, который ловит JavaScript-ошибки в дочерних компонентах и позволяет показать запасной интерфейс вместо "сломавшегося" компонента.

Дословный перевод

Error = ошибка
Boundary = граница, предел, рубеж
Но в программировании лучше использовать термин "Граница ошибок" или "Перехватчик ошибок".

Почему именно "граница"?

javascript
// Представьте, что ваше приложение - это дом

  <Header />          // Крыльцо
    
  <Main>              // Основная часть дома
    <Sidebar />       // Комната 1
    <Content>         // Комната 2
      <Widget />      // Мебель в комнате 2
    </Content>
  </Main>
  
  <Footer />          // Фундамент
</App>

    <Sidebar />

        <Widget />    // Если здесь пожар (ошибка)
      </Content>
    </ErrorBoundary>  // 🔥 Огонь не пойдет дальше
  </Main>
  
  <Footer />
</App>

Дженерики (Generics) в TypeScript

Дженерики (от англ. "generic" — общий, родовой) — это инструмент, который позволяет создавать компоненты, работающие с любыми типами, но при этом сохраняющие информацию о типе. Это как "переменные для типов".

class ApiClient {
  async get<T>(url: string): Promise<T> {
    const response = await fetch(url);
    const data = await response.json();
    return data as T;
  }
  
  async post<T, U>(url: string, data: T): Promise<U> {

      method: 'POST',
      body: JSON.stringify(data)
    });
    return await response.json();
  }

// hooks/useApi.ts
function useApi<T>() {
  const [data, setData] = useState<T | null>(null);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState<Error | null>(null);
  
  const client = new ApiClient();
  
  const fetchData = async (url: string) => {
    setLoading(true);
    try {
      const result = await client.get<T>(url);
      setData(result);
    } catch (err) {
      setError(err as Error);
    } finally {
      setLoading(false);
    }
  };
  
  return { data, loading, error, fetchData };
}

6. Как это используется в React

class SimpleErrorBoundary extends React.Component<Props, State> {
  state: State = {
    hasError: false,  // Начинаем с false - ошибки нет
    error: null,      // Объекта ошибки тоже нет
  };

  static getDerivedStateFromError(error: Error): Partial<State> {
    // Когда происходит ошибка, React вызывает этот метод
    // и обновляет состояние
    return {
      hasError: true,   // Меняем на true
      error: error      // Сохраняем объект ошибки
    };
  }

  render() {
    // Используем состояние для условного рендеринга
    if (this.state.hasError) {
      // Показываем запасной UI с информацией об ошибке
      return (
        <div>
          <h2>Что-то пошло не так</h2>
          <p>{this.state.error?.message}</p>
        </div>
      );
    }
    
    // Если ошибки нет, рендерим дочерние компоненты
    return this.props.children;
  }
}

11. Практический пример с TypeScript

typescript
interface Props {
  children: React.ReactNode;
  fallback?: React.ReactNode;
  onError?: (error: Error) => void;
}

interface State {
  hasError: boolean;
  error: Error | null;
  errorCount: number;        // счетчик ошибок
  lastErrorTime: Date | null; // время последней ошибки
}

export class AdvancedErrorBoundary extends React.Component<Props, State> {
  // Инициализация состояния
  state: State = {
    hasError: false,
    error: null,
    errorCount: 0,
    lastErrorTime: null
  };

  static getDerivedStateFromError(error: Error): Partial<State> {
    // Обновляем состояние при ошибке
    return {
      hasError: true,
      error: error,
      errorCount: 0, // это будет перезаписано в componentDidCatch
      lastErrorTime: new Date()
    };
  }

  componentDidCatch(error: Error) {
    // Обновляем счетчик ошибок
    this.setState(prevState => ({
      errorCount: prevState.errorCount + 1
    }));
    
    // Вызываем колбэк
    this.props.onError?.(error);
  }

  render() {
    if (this.state.hasError) {
      // Используем все поля состояния
      return (
        <div>
          {this.props.fallback || (
            <>
              <h2>Ошибка #{this.state.errorCount}</h2>
              <p>{this.state.error?.message}</p>
              <p>Время: {this.state.lastErrorTime?.toLocaleString()}</p>
            </>
          )}
        </div>
      );
    }
    
    return this.props.children;
  }
}

1. Разбор по частям

static — статический метод

typescript
static getDerivedStateFromError() { ... }
Метод принадлежит классу, а не экземпляру
Вызывается до того, как создан экземпляр компонента
Не имеет доступа к this (не может использовать this.state или this.props)
getDerivedStateFromError — название метода

getDerived — получить производное/вычисленное
State — состояние
FromError — из ошибки
Буквально: "получить состояние из ошибки"

(error: Error) — параметр

typescript
(error: Error) // React передает объект ошибки
error — объект ошибки, который был выброшен
Тип Error — стандартный тип для ошибок в JS/TS
: Partial<State> — возвращаемый тип

typescript
: Partial<State> // возвращает частичное состояние
Partial (утилитарный тип, который делает все свойства типа необязательными) <State> означает, что возвращается часть объекта State
Не нужно возвращать всё состояние, только то, что изменилось

return { hasError: true, error } - что возвращаем
hasError: true — флаг, что произошла ошибка
error: error — сохраняем объект ошибки

static getDerivedStateFromError() — метод жизненного цикла React для обработки ошибок

Это статический метод в React-компонентах, который вызывается, когда в дочернем компоненте происходит ошибка. Он позволяет обновить состояние компонента-перехватчика ошибок (Error Boundary).

Как это работает

javascript
static getDerivedStateFromError(error) {
  // Вызывается после ошибки в дочернем компоненте
  // Получает ошибку как параметр
  // Должен вернуть объект для обновления состояния
  return { hasError: true, error };
}
Полный пример Error Boundary

javascript
import React, { Component } from 'react';

class ErrorBoundary extends Component {
  constructor(props) {
    super(props);
    this.state = {
      hasError: false,
      error: null,
      errorInfo: null
    };
  }

  // 1. СНАЧАЛА вызывается этот метод
  static getDerivedStateFromError(error) {
    // Обновляем состояние, чтобы показать fallback UI
    console.log('1. getDerivedStateFromError поймал ошибку:', error);
    
    return {
      hasError: true,  // показываем, что ошибка произошла
      error: error     // сохраняем ошибку для отображения
    };
  }

  // 2. ПОТОМ вызывается componentDidCatch (если есть)
  componentDidCatch(error, errorInfo) {
    // Здесь можно отправить ошибку в сервис логирования
    console.log('2. componentDidCatch отправил ошибку в лог:', error, errorInfo);
    
    // Отправляем в Sentry / LogRocket / свой сервис
    logErrorToService(error, errorInfo);
  }

  render() {
    // 3. ИСПОЛЬЗУЕМ обновленное состояние для рендера
    if (this.state.hasError) {
      // Показываем запасной UI
      return (
        <div className="error-boundary-fallback">
          <h2>Что-то пошло не так</h2>
          <details>
            <summary>Детали ошибки</summary>
            <p>{this.state.error?.toString()}</p>
          </details>
          <button onClick={() => window.location.reload()}>
            Обновить страницу
          </button>
        </div>
      );
    }

    // Если ошибки нет, рендерим дочерние компоненты
    return this.props.children;
  }
}

// Использование
function App() {
  return (
    <ErrorBoundary>
      <MyComponent />
    </ErrorBoundary>
  );
}

class AdvancedErrorBoundary extends Component {
  state = {
    hasError: false,
    error: null,
    errorType: null
  };

  static getDerivedStateFromError(error) {
    // Определяем тип ошибки для разного отображения
    let errorType = 'unknown';
    
    if (error instanceof TypeError) {
      errorType = 'type';
    } else if (error instanceof ReferenceError) {
      errorType = 'reference';
    } else if (error.message.includes('network')) {
      errorType = 'network';
    } else if (error.message.includes('auth')) {
      errorType = 'auth';
    }
    
    // Сохраняем информацию об ошибке
    return {
      hasError: true,
      error: error,
      errorType: errorType,
      timestamp: new Date().toISOString()
    };
  }

  componentDidCatch(error, errorInfo) {
    // Логируем с дополнительной информацией
    console.group('Error Boundary Catch');
    console.log('Тип ошибки:', this.state.errorType);
    console.log('Ошибка:', error);
    console.log('Компонент:', errorInfo.componentStack);
    console.groupEnd();

    fetch('/api/log-error', {
      method: 'POST',

        type: this.state.errorType,
        stack: error.stack,
        componentStack: errorInfo.componentStack,
        timestamp: this.state.timestamp,
        url: window.location.href,
        userAgent: navigator.userAgent
      })
    });
  }

  getErrorMessage() {
    const { errorType, error } = this.state;
    
    const messages = {
      type: 'Произошла ошибка типов данных',
      reference: 'Обращение к несуществующей переменной',

      auth: 'Ошибка авторизации. Войдите снова',
      unknown: error?.message || 'Неизвестная ошибка'
    };
    
    return messages[errorType] || messages.unknown;
  }

    if (this.state.hasError) {
      return (

Комбинация с разными fallback UI

javascript
class ErrorBoundary extends Component {
  state = { hasError: false, error: null };

  static getDerivedStateFromError(error) {
    return { hasError: true, error };
  }

  render() {
    if (this.state.hasError) {
      // Можно использовать разные fallback в зависимости от props
      if (this.props.fallback) {
        return this.props.fallback;
      }
      
      // Или кастомный компонент ошибки
      if (this.props.FallbackComponent) {
        return <this.props.FallbackComponent error={this.state.error} />;
      }
      
      // Или функцию, которая возвращает UI
      if (typeof this.props.fallbackRender === 'function') {
        return this.props.fallbackRender({ error: this.state.error });
      }
      
      // По умолчанию
      return <DefaultFallback error={this.state.error} />;
    }

    return this.props.children;
  }
}

Статические методы в классах JavaScript/TypeScript

Статические методы — это методы, которые принадлежат самому классу, а не его экземплярам. Они вызываются через класс, а не через объекты, созданные от этого класса.

Базовый синтаксис

javascript
class MyClass {
  static myMethod() {
    console.log('Это статический метод');
  }
  
  regularMethod() {
    console.log('Это обычный метод');
  }
}

// Вызов статического метода
MyClass.myMethod(); // ✅ "Это статический метод"

// ❌ Нельзя вызвать через экземпляр
const obj = new MyClass();
obj.myMethod(); // Ошибка! obj.myMethod is not a function

// Обычный метод можно вызвать только через экземпляр
obj.regularMethod(); // ✅ "Это обычный метод"
MyClass.regularMethod(); // Ошибка!

    if (this.connected) {
      DatabaseConnection.#instanceCount--;
      this.connected = false;
      console.log(`Подключение #${this.id} закрыто`);
    }
  }

class Validator {
  static rules = {
    email: /^[^\s@]+@[^\s@]+\.[^\s@]+$/,
    phone: /^\+?[\d\s-]{10,}$/,
    url: /^(https?:\/\/)?([\da-z.-]+)\.([a-z.]{2,6})([/\w .-]*)*\/?$/
  };
  
  static validateEmail(email) {
    return this.rules.email.test(email);
  }
  
  static validatePhone(phone) {
    return this.rules.phone.test(phone);
  }
  
  static validateUrl(url) {
    return this.rules.url.test(url);
  }
  
  static validateRequired(value) {
    return value !== null && value !== undefined && value !== '';
  }
  
  static validateLength(value, min, max) {
    const length = String(value).length;
    return length >= min && length <= max;
  }
  
  static validateForm(data, validationRules) {
    const errors = {};
    
    for (const [field, rules] of Object.entries(validationRules)) {
      const value = data[field];
      
      if (rules.required && !Validator.validateRequired(value)) {
        errors[field] = 'Поле обязательно';
        continue;
      }
      
      if (rules.email && !Validator.validateEmail(value)) {
        errors[field] = 'Некорректный email';
      }
      
      if (rules.minLength && value.length < rules.minLength) {
        errors[field] = `Минимум ${rules.minLength} символов`;
      }
      
      if (rules.maxLength && value.length > rules.maxLength) {
        errors[field] = `Максимум ${rules.maxLength} символов`;
      }
    }
    
    return {
      isValid: Object.keys(errors).length === 0,
      errors
    };
  }
}

Полный рабочий пример

typescript
import React from 'react';

// Определяем типы
interface Props {
  children: React.ReactNode;      // что оборачиваем
  fallback?: React.ReactNode;      // запасной UI (опционально)
  onError?: (error: Error, errorInfo: React.ErrorInfo) => void; // колбэк при ошибке
}

interface State {
  hasError: boolean;  // была ли ошибка
  error: Error | null; // информация об ошибке
}

// Класс-перехватчик ошибок
export class SimpleErrorBoundary extends React.Component<Props, State> {
  // Инициализация состояния с типизацией
  state: State = {
    hasError: false,
    error: null,
  };

  // Статический метод - вызывается при ошибке
  static getDerivedStateFromError(error: Error): Partial<State> {
    // Обновляем состояние, чтобы показать fallback UI
    return {
      hasError: true,
      error: error
    };
  }

  // Вызывается после ошибки (для логирования)
  componentDidCatch(error: Error, errorInfo: React.ErrorInfo) {
    // Вызываем колбэк, если передан
    if (this.props.onError) {
      this.props.onError(error, errorInfo);
    }
    
    // Логируем ошибку
    console.error('Поймана ошибка:', error, errorInfo);
  }

  // Сброс ошибки (например, при повторной попытке)
  resetError = () => {
    this.setState({
      hasError: false,
      error: null
    });
  };

  render() {
    // Если есть ошибка - показываем fallback UI
    if (this.state.hasError) {
      // Если передан кастомный fallback - используем его
      if (this.props.fallback) {
        return this.props.fallback;
      }
      
      // Иначе показываем стандартный fallback
      return (
        <div className="error-boundary-fallback">
          <h2>Что-то пошло не так</h2>
          <details>
            <summary>Детали ошибки</summary>
            <p>{this.state.error?.toString()}</p>
          </details>
          <button onClick={this.resetError}>
            Попробовать снова
          </button>
        </div>
      );
    }

    // Если ошибки нет - рендерим дочерние компоненты
    return this.props.children;
  }
}

error boundary переведи в контексте программирования
Error Boundary — что это в программировании?

Error Boundary (читается как "Эррор Баундари") — это компонент-перехватчик ошибок или граница ошибок. Это механизм в React, который ловит JavaScript-ошибки в дочерних компонентах и позволяет показать запасной интерфейс вместо "сломавшегося" компонента.

Дословный перевод

Error = ошибка
Boundary = граница, предел, рубеж
Но в программировании лучше использовать термин "Граница ошибок" или "Перехватчик ошибок".

Почему именно "граница"?

javascript
// Представьте, что ваше приложение - это дом
<App>                 // Весь дом
  <Header />          // Крыльцо
    
  <Main>              // Основная часть дома
    <Sidebar />       // Комната 1
    <Content>         // Комната 2
      <Widget />      // Мебель в комнате 2
    </Content>
  </Main>
  
  <Footer />          // Фундамент
</App>

// Error Boundary создает "противопожарные стены" между комнатами
<App>
  <Header />
  
  <Main>
    <Sidebar />
    <ErrorBoundary>   // 🔥 Противопожарная стена
      <Content>
        <Widget />    // Если здесь пожар (ошибка)
      </Content>
    </ErrorBoundary>  // 🔥 Огонь не пойдет дальше
  </Main>
  
  <Footer />
</App>

Дженерики (Generics) в TypeScript

Дженерики (от англ. "generic" — общий, родовой) — это инструмент, который позволяет создавать компоненты, работающие с любыми типами, но при этом сохраняющие информацию о типе. Это как "переменные для типов".

  items: T[];

    <ul>
      {items.map((item, index) => (

        </li>
      ))}
    </ul>
  );
}

  const [data, setData] = useState<T | null>(null);

    } finally {
      setLoading(false);
    }
  };

class SimpleErrorBoundary extends React.Component<Props, State> {
  state: State = {
    hasError: false,  // Начинаем с false - ошибки нет
    error: null,      // Объекта ошибки тоже нет
  };

  static getDerivedStateFromError(error: Error): Partial<State> {
    // Когда происходит ошибка, React вызывает этот метод
    // и обновляет состояние
    return {
      hasError: true,   // Меняем на true
      error: error      // Сохраняем объект ошибки
    };
  }

  render() {
    // Используем состояние для условного рендеринга
    if (this.state.hasError) {
      // Показываем запасной UI с информацией об ошибке
      return (
        <div>
          <h2>Что-то пошло не так</h2>
          <p>{this.state.error?.message}</p>
        </div>
      );
    }
    
    // Если ошибки нет, рендерим дочерние компоненты
    return this.props.children;
  }
}

11. Практический пример с TypeScript

typescript
interface Props {
  children: React.ReactNode;
  fallback?: React.ReactNode;
  onError?: (error: Error) => void;
}

interface State {
  hasError: boolean;
  error: Error | null;
  errorCount: number;        // счетчик ошибок
  lastErrorTime: Date | null; // время последней ошибки
}

export class AdvancedErrorBoundary extends React.Component<Props, State> {
  // Инициализация состояния
  state: State = {
    hasError: false,
    error: null,
    errorCount: 0,
    lastErrorTime: null
  };

  static getDerivedStateFromError(error: Error): Partial<State> {
    // Обновляем состояние при ошибке
    return {
      hasError: true,
      error: error,
      errorCount: 0, // это будет перезаписано в componentDidCatch
      lastErrorTime: new Date()
    };
  }

  componentDidCatch(error: Error) {
    // Обновляем счетчик ошибок
    this.setState(prevState => ({
      errorCount: prevState.errorCount + 1
    }));
    
    // Вызываем колбэк
    this.props.onError?.(error);
  }

  render() {
    if (this.state.hasError) {
      // Используем все поля состояния
      return (
        <div>
          {this.props.fallback || (
            <>
              <h2>Ошибка #{this.state.errorCount}</h2>
              <p>{this.state.error?.message}</p>
              <p>Время: {this.state.lastErrorTime?.toLocaleString()}</p>
            </>
          )}
        </div>
      );
    }
    
    return this.props.children;
  }
}

Подробный разбор метода getDerivedStateFromError

Это статический метод жизненного цикла React, который вызывается, когда в дочернем компоненте происходит ошибка. Давайте разберем каждую часть:

Полный метод

typescript
static getDerivedStateFromError(error: Error): Partial<State> {
    // обновляем состояние так, чтобы следующий рендер показал fallback UI
    return { hasError: true, error };
}
1. Разбор по частям

static — статический метод

typescript
static getDerivedStateFromError() { ... }
Метод принадлежит классу, а не экземпляру
Вызывается до того, как создан экземпляр компонента
Не имеет доступа к this (не может использовать this.state или this.props)
getDerivedStateFromError — название метода

getDerived — получить производное/вычисленное
State — состояние
FromError — из ошибки
Буквально: "получить состояние из ошибки"

(error: Error) — параметр

typescript
(error: Error) // React передает объект ошибки
error — объект ошибки, который был выброшен
Тип Error — стандартный тип для ошибок в JS/TS
: Partial<State> — возвращаемый тип

typescript
: Partial<State> // возвращает частичное состояние
Partial<State> означает, что возвращается часть объекта State
Не нужно возвращать всё состояние, только то, что изменилось
return { hasError: true, error }; — что возвращаем

typescript
return { hasError: true, error };
Возвращаем объект с двумя полями:

hasError: true — флаг, что произошла ошибка
error: error — сохраняем объект ошибки
2. Как это работает внутри React

typescript
// Псевдокод того, как React вызывает этот метод
class ReactInternal {
  handleErrorInChild(component: Component, error: Error) {
    // 1. Вызываем статический метод
    const partialState = component.constructor.getDerivedStateFromError(error);
    
    // 2. Обновляем состояние компонента
    component.setState(partialState);
    
    // 3. Запускаем перерендер
    component.forceUpdate();
  }
}
3. Полный пример с пояснениями

typescript
interface State {
  hasError: boolean;
  error: Error | null;
  errorCount?: number; // опционально
  timestamp?: Date;    // опционально
}

class ErrorBoundary extends React.Component<{}, State> {
  state: State = {
    hasError: false,
    error: null
  };

  // React вызывает этот метод, когда дочерний компонент выбрасывает ошибку
  static getDerivedStateFromError(error: Error): Partial<State> {
    // 🎯 ЦЕЛЬ: Подготовить состояние для показа fallback UI
    
    console.log('1. Поймана ошибка:', error.message);
    
    // Возвращаем объект с обновленными полями
    return {
      hasError: true,  // меняем флаг
      error: error     // сохраняем ошибку
    };
    
    // React автоматически смержит этот объект с текущим состоянием
    // Новое состояние станет: { hasError: true, error: Error, ... остальные поля }
  }

  componentDidUpdate(prevProps: {}, prevState: State) {
    // Этот метод вызовется после того, как getDerivedStateFromError обновил состояние
    if (this.state.hasError && !prevState.hasError) {
      console.log('2. Состояние обновлено, показываем fallback UI');
    }
  }

  render() {
    // Используем обновленное состояние
    if (this.state.hasError) {
      // Показываем fallback UI
      return (
        <div className="error-fallback">
          <h2>Произошла ошибка</h2>
          <p>{this.state.error?.message}</p>
        </div>
      );
    }
    
    return this.props.children;
  }
}

interface ExtendedState {

class AdvancedErrorBoundary extends React.Component<{}, ExtendedState> {
  state: ExtendedState = {
    hasError: false,
    error: null,
    errorType: null,
    timestamp: null,
    retryCount: 0
  };

  static getDerivedStateFromError(error: Error): Partial<ExtendedState> {
    // Определяем тип ошибки
    let errorType: ExtendedState['errorType'] = 'runtime';
    
    if (error.message.includes('network')) {
      errorType = 'network';
    } else if (error.message.includes('validation')) {
      errorType = 'validation';
    }
    
    // Возвращаем только изменившиеся поля
    return {
      hasError: true,
      error: error,
      errorType: errorType,
      timestamp: new Date()
      // retryCount НЕ возвращаем - останется как был
    };
  }

  componentDidCatch(error: Error) {
    // Увеличиваем счетчик попыток
    this.setState(prevState => ({
      retryCount: prevState.retryCount + 1
    }));
  }

  render() {
    if (this.state.hasError) {
      // Используем все поля состояния
      return (
        <div className={`error error-${this.state.errorType}`}>
          <h2>Ошибка #{this.state.retryCount}</h2>
          <p>Тип: {this.state.errorType}</p>
          <p>Время: {this.state.timestamp?.toLocaleString()}</p>
          <p>Детали: {this.state.error?.message}</p>
        </div>
      );
    }
    
    return this.props.children;
  }

typescript
// 1. Метод вызывается при любой ошибке в дочерних компонентах
// 2. Не ловит ошибки в:
//    - Асинхронном коде (setTimeout, Promise)
//    - Событиях (onClick и т.д.)
//    - Серверном рендеринге
//    - Ошибках в самом ErrorBoundary

// 3. Возвращаемый объект МЕРДЖИТСЯ с текущим состоянием
static getDerivedStateFromError(error: Error) {
  // Текущее состояние: { hasError: false, error: null, retryCount: 5 }

  // Новое состояние: { hasError: true, error: Error, retryCount: 5 }
  // retryCount сохранился!

// 4. Можно вернуть null, если не хотите обновлять состояние
static getDerivedStateFromError(error: Error) {
  if (shouldIgnoreError(error)) {
    return null; // состояние не изменится
  }
  return { hasError: true, error };
}
Кратко: getDerivedStateFromError — это статический метод, который React вызывает при ошибке в дочернем компоненте. Он получает объект ошибки и должен вернуть объект с обновленными полями состояния (обычно hasError: true и саму ошибку). После этого React обновляет состояние и запускает перерендер, чтобы показать fallback UI вместо сломавшегося компонента.

  create(data: Omit<Todo, 'id' | 'createdAt' | 'updatedAt'>): Todo {
    const newTodo: Todo = {
      ...data,
      id: Math.random().toString(36),
      createdAt: new Date(),
      updatedAt: new Date()
    };
    this.todos.push(newTodo);
    return newTodo;
  }
  
  // UPDATE - только измененные поля
  update(id: string, updates: Partial<Omit<Todo, 'id' | 'createdAt'>>): Todo {
    const index = this.todos.findIndex(t => t.id === id);
    
    this.todos[index] = {
      ...this.todos[index],
      ...updates,
      updatedAt: new Date() // всегда обновляем
    };
    
    return this.todos[index];
  }
  
  // SEARCH - частичные критерии
  search(criteria: Partial<Todo>): Todo[] {
    return this.todos.filter(todo => {
      return Object.entries(criteria).every(([key, value]) => {
        return todo[key as keyof Todo] === value;
      });
    });
  }
  
  // BATCH UPDATE - обновить много задач
  batchUpdate(ids: string[], updates: Partial<Todo>): Todo[] {
    return ids.map(id => this.update(id, updates));
  }
}

  text: "Купить молоко",
  completed: false,
  tags: ["покупки"],

});

// Обновление (только completed)

         data.name.length > 0 &&
         data.email.includes('@');

    // TypeScript знает, что здесь есть name и email

      id: Date.now(),
      name: data.name,    // ✅ не undefined
      email: data.email,  // ✅ не undefined
      age: data.age
    };
  }
  throw new Error('Недостаточно данных');

interface ComplexType {
  required: string;                    // обязательное
  optional?: number;                    // опциональное
  nested: {                             // вложенный объект
    field1: boolean;
    field2: string[];
  };
  union: string | number;               // union тип
  readonly readonlyField: Date;         // readonly
}

// 1. Partial делает все поля опциональными, но не рекурсивно
type PartialComplex = Partial<ComplexType>;

// nested стал опциональным, но внутри обязательные поля остались
const test1: PartialComplex = {
  nested: { field1: true } // ❌ ошибка! нужно поле field2
};

// 2. Решение: DeepPartial
type DeepPartial<T> = {
  [P in keyof T]?: T[P] extends object ? DeepPartial<T[P]> : T[P];
};

const test2: DeepPartial<ComplexType> = {
  nested: { field1: true } // ✅ работает!
};

// 3. Optional поля остаются optional
type Result = Partial<{ required: string; optional?: number }>;
// { required?: string; optional?: number } - optional уже был optional

componentDidCatch ("компонент поймал ошибку" (уже после того, как поймал)) - это метод жизненного цикла React, который вызывается после того, как ошибка была поймана в дочернем компоненте. Он используется для побочных эффектов (легирование, отправка ошибок в аналитику).

errorInfo — дополнительная информация (где произошла ошибка)
interface ErrorInfo {
  componentStack: string; // стек компонентов (где произошла ошибка)
}

 componentStack - это строка, содержащая стек вызовов React-компонентов, которая показывает, где именно в иерархии компонентов произошла ошибка. Он показывает путь от корневого компонента до того места, где произошла ошибка.


Fallback (произносится "фолбэк") — это запасной вариант, резервный план или что-то, что используется, когда основной вариант не сработал.
