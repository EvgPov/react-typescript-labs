Маршрутизация - это механизм, который сопоставляет URL и экран приложения.
URL (Uniform Resource Locator) - это адрес ресурса в интернете.
Маршрутизация отвечает на вопрос: "Какой интерфейс нужно показать, если пользователь открыл вот это адрес?"

Маршрут - это правило, которое связывает:
	- путь в адресной строке
	- компонент, который должен быть показан

Маршрутизация строится вокруг простой мысли:
 URL - это часть состояния приложения.
Если адрес изменился, интерфейс тоже должен измениться.

Маршрутизация на сервере (server-side routing):
	- пользователь открывает адрес
	- браузер отправляет HTTP-запрос на сервер
	- сервер смотрит на путь
	- сервер решает, какую HTML-страницу вернуть
	- браузер полностью загружает новую страницу

Клиентская маршрутизация на SPA- Single Page Application (client-side routing):
	- браузер один раз загружает базовый HTML и JavaScript
	- дальше React работает внутри браузера
	- при переходе между экранами страница физически не перезагружается
	- меняется URL и React показывает другой экран
Решение о том, какой экран отрисовать, принимает клиентский код, а не сервер.

Отличия:
	- северная маршрутизация
		новый запрос к серверу
		новая HTML- страница
		полняа перезагрузка документа
	- клиентская марщшрутизация
		документ не перезагружается
		URL меняется через браузерный API
		React перерисовывает нужный экран внутри уже загруженного приложения


Преимущества клиентской мапшрутизации:
	- более быстрые переходы между страницами
	- меньше визуальных миганий
	- ощущение "приложения", а не набора HTML- страниц
	- гибкая логика навигации
	- удобная работа с состоянием на клиенте

Сервер все равно участвует.
	Если пользователь:
		- откроет /profile напрямую
		- нажмет F5
		- вставит ссылку в новый таб
Браузер все равно сначала отправит запрос на сервер по адресу /profile.
И сервер должен корректно вернуть базовую страницу приложения, чтобы React уже потом разобрал путь и показал нужный экран.


Сервер должен быть настроен так, чтобы почти для всех путей возвращать один и тот же базовый HTML приложения.
Тогда:
	- React загрузится
	- увидит текущий путь
	- сам нарисует нужную страницу

React Router относится к клиентской маршрутизауии, но для корректной работы прямых переходов и обновлений страницы сервер все равно должен быть правильно настроен.


Регидратация - это процесс, при котором:
	- сервер заранее отрисовывает HTML-страницы
	- браузер получает уже готовую разметку
	- заем React на клиенте "подключается" к этой разметке и делает ее интерактивный
То есть сначала пользователь видит уже готовы HTML, а потом React удивляет его.

Это используется, когдаьзотят совместить преимущества
	- северного рендера
	- клиентской навигации
Плюсы:
	- страница быстрее показывает первый контакт
	- лучше для SEO (Search Engine Optimization) - это поисковая оптимизация, то есть комплекс действий, направленных на то, чтобы сайт занимал высокие позиции (был ближе к топ-10) в результатах поиска Яндекс, Google и других систем по нужным запроса.
	- прямой переход по URL работает естественно
	- потом приложение продолжает жить как SPA
При таком подходе:
	1. Пользователь открывает /product/42
	2. Сервер понимает маршрут /product/42
	3. Сервер рендерит HTML нудной страницы
	4. браузер показывает эту HTML-страницу
	5. React на клиенте гидратирует её
	6. после этого дальнейшие переходы уже могут идти как в SPA

То есть маршрутизация:
	- частично учитывает на сервере
	- а потом продолжается на клиенте

Обычный клиентский рендер
	- сервер отдал почти пустой HTML
	- браузер скачал JS
	- React сам все анрисова
Гидратация
	- сервер уже отдал готовый HTML
	- React не рисует все заново с нуля
	- он "прикрепляет" обработки событий и связывает этот HTML со своими компонентами

History API - это набор возможностей браузера для работы с историей навигации.
Он позволяет:
	- добавлять запись в историю
	- заменять текущуюю запись
	- узнавать текущий путь
	- реагировать переходы назад/вперед

	Метод pushState добавляет новую запись в историю браузера и меняет URL без перегрузки страницы.

window.history.pushState({}, '', '/about');

Что произойдёт
адресная строка изменится на /about
страница не перезагрузится
новая запись появится в истории браузера
Именно на этом принципе строится переход между страницами в SPA.

	Метод replaceState тоже менят URL без перезагрузки, но не добавляет новую запись в историю, а замеряет текущую.

window.history.replaceState({}, '', '/login');

Когда это полезно
Например:
после редиректа;
при замене URL после авторизации;
когда не хочется, чтобы пользователь возвращался на промежуточный адрес кнопкой Back.

	Метод popState()
Когда пользователь нажимает “назад” или “вперёд”, браузер может сообщить об этом через событие popstate.
window.addEventListener('popstate', () => {
  console.log(window.location.pathname);
});

Это позволяет приложению узнать, что история изменилась, и обновить интерфейс.

React Router - это библиотека маршрутизации в React-приложениях.
Она помогает:
	- связать URL и компоненты
	- строить навигацию без одной перегрузки страницы
	- работать с параметрами маршрута
	- обрабатывать вложенные маршруты
	- использовать историю браузера

1. BrowserRouter - это компонент, который подключает React Router к браузреной истории.
Обычно им оборачивают все приложение.
	- следит за текущим URL
	- синхронизирует React Router с History API
	- дает вложенным компонентам доступ к маршрутизации
2. Routes и Route
	Routes - контейнер для списка маршрутов
	Route - отдельное правило сопоставления пути и компонента
import { Routes, Route } from 'react-router-dom';

function HomePage() {
  return <h1>Главная</h1>;
}

function AboutPage() {
  return <h1>О нас</h1>;
}
function NotFoundPage() {
  return <h1>Страница не найдена</h1>;
}


export function App() {
  return (
    <Routes>
      <Route path="/" element={<HomePage />} />
      <Route path="/about" element={<AboutPage />} />
      <Route path="*" element={<NotFoundPage />} />
    </Routes>
  );
}

* - маршрут - ловушка для всех путей, которые не совпали с остальными.


Вложенные маршруты

Это полезно, когда у них есть общий layout

Outlet - это место внутри layout, куда React Router вставляет дочерний маршрут

	- layout всегда остается на экране
	- меняется только содержимое внутри Outlet



import { Routes, Route, Outlet } from 'react-router-dom';

function Layout() {
  return (
    <div>
      <header>Шапка</header>
      <main>
        <Outlet />
      </main>
      <footer>Футер</footer>
    </div>
  );
}

function HomePage() {
  return <h1>Главная</h1>;
}

function AboutPage() {
  return <h1>О нас</h1>;
}

export function App() {
  return (
    <Routes>
      <Route path="/" element={<Layout />}>
        <Route index element={<HomePage />} />
        <Route path="about" element={<AboutPage />} />
      </Route>
    </Routes>
  );
}
index во вложенных маршрутах

 <Route index element={<HomePage />} />
Означает маршрут по умолчанию для родительского пути.
Если родитель — /, то index-маршрут будет показан на /.

	- то, что есть на каждой странице (это Layout)
	- то, что меняется (это Outlet)
Outlet — это просто пустое место в Layout, которое React Router заполняет содержимым текущей страницы.
	- index — это маршрут по умолчанию для родительского пути.

Если родительский путь = /
То index маршрут сработает именно на /
Без index при открытии / внутри Outlet было бы пусто.

Layout	- компонент с общей частью для нескольких страниц	
Outlet	- место в Layout, куда вставляется содержимое
index	- маршрут для точного совпадения с родительским путем

Потому что обычный тег <a>:
заставляет браузер делать полный переход;
может привести к полной перезагрузке страницы;
ломает идею клиентской маршрутизации.


Для навигации в React Router используют Link

Link:
	- меняет URL
	- не перегружают с границу
	- использует внутренний механизм Router
	- добавляет запись в историю
import { Link } from 'react-router-dom';

function Navigation() {
  return (
    <nav>
      <Link to="/">Главная</Link>
      <Link to="/about">О нас</Link>
      <Link to="/profile">Профиль</Link>
    </nav>
  );
}

NavLink полезен, когда нужно понимать, активна ли ссылка

Например, для меню.
import { NavLink } from 'react-router-dom';

function Navigation() {
  return (
    <nav>
      <NavLink to="/">Главная</NavLink>
      <NavLink to="/about">О нас</NavLink>
    </nav>
  );
}

NavLink умеет определять, совпадает ли текущий путь со ссылкой.
<NavLink
  to="/about"
  className={({ isActive }) => (isActive ? 'active-link' : '')}
>
  О нас
</NavLink

Иногда переход должен происходить не по ссылке, а после действия:
	- после отправки формы
	- после логина
	- после удалления
	- после нажатия кнопки "Назад"
Для этого ест useNavigate
import { useNavigate } from 'react-router-dom';

function LoginPage() {
  const navigate = useNavigate();

  function handleLogin() {
    // логика входа
    navigate('/profile');
  }

  return <button onClick={handleLogin}>Войти</button>;
}

Можно делать навигацию по истории:
 navigate(-1)
Это аналог нажатия кнопки Back
Если не хочется добавлять запись в историю:
navigate('/profile', { replace: true });

Динамические параметры маршрута:

<Route path="/users/:id" element={<UserPage />} />
:id - это переменный сегмент пути.
React Router понимает, что на этом месте может быть разное значение.
Для получения параметра используется хук useParams

import { useParams } from 'react-router-dom';

function UserPage() {
  const params = useParams();

  return <h1>Пользователь: {params.id}</h1>;
}

Даже если в URL число, useParams() возвращает строку.
Если нужно число, его надо преобразовать вручную.
const { id } = useParams();
const userId = Number(id);

Нужно различать  Query-параметры и path-параметры

Path-параметры:
	- часть пути
	/users/:id
	пример: /users/42

Query-параметры:
	- Часть после ?:
/products?category=phones&page=2

Это другой механизм.
Для них часто используют useSearchParams.


Сами page-компоненты типизируются как обычные React-компоненты.
Но если данные приходят не через props, а через Router-хуки, нужно отдельно типизировать то, что мы извлекаем.

Очень важный момент: параметры из useParams() могут быть undefined.
Например:
const { id } = useParams();

TypeScript может понимать id как:
string | undefined

Почему?
Потому что с точки зрения типов React Router не может абсолютно гарантировать, что параметр точно существует в каждый момент.
Вариант 1. Проверка
const { id } = useParams();

if (!id) {
  return <p>Параметр id не найден</p>;
}

return <p>ID: {id}</p>;

Вариант 2. Явное приведение после проверки
const { id } = useParams();

if (!id) return null;

const userId = Number(id);

Часто делают так:
type UserParams = {
  id: string;
};

const { id } = useParams() as UserParams;

Но здесь важно:
это уже более “жёсткий” путь, где мы сами утверждаем, что параметр существует.

const { id } = useParams();
const numericId = Number(id);

if (Number.isNaN(numericId)) {
  return <p>Некорректный id</p>;
}

export const ROUTES = {
  HOME: '/',
  ABOUT: '/about',
  PROFILE: '/profile',
  USER: '/users/:id',
} as const;

Использование:
<Link to={ROUTES.PROFILE}>Профиль</Link>
navigate(ROUTES.PROFILE);
<Route path={ROUTES.PROFILE} element={<ProfilePage />} />

Если есть маршрут:
USER: '/users/:id'

то для перехода на конкретного пользователя удобно писать функцию:
export function getUserRoute(id: string) {
  return `/users/${id}`;
}

Использование:
<Link to={getUserRoute('42')}>Пользователь</Link>
navigate(getUserRoute('42'));

Это лучше, чем вручную собирать строки по всему приложению.
Иногда при навигации передают дополнительные данные:
navigate('/profile', {
  state: { from: 'login' },
});

На странице можно получить их через useLocation.
Но здесь важно помнить:
эти данные могут отсутствовать;
после обновления страницы они могут потеряться;
их тоже нужно безопасно проверять.
То есть это не замена полноценным параметрам URL или глобальному состоянию.
