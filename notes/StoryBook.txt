Children - это все содержимое, которое находится между открывающим и закрывающим тегом компонента, когда вы его используете.

Изолированный компонент:
- зависит только от props
- не читает глобальные переменные, localStorage, контекст
- можно отрисовать отдельно от приложения
- легко тестировать и документировать

Главное правильно изоляции:
Компонент = чистая функция (чистая функция - это функция, которая всегда возвращает один и то. же результат при одинаковых входных данных и не имеет побочных эффектов).
1. Детерминированность
При одинаковых аргументах -> всегда одинаковый результат
2. Нет побочных эффектов, то есть функция не изменяет ничего снаружи себя:
	- не меняет глобальные переменные
	- не мутирует переданные объекты/массивы
	- не работает с внешним состоянием
	- не изменяя входные данные (не мутирует аргументы)
3. Не зависит от внешнего состояния
Не читает ничего, кроме своих аргументов


Правила "чистоты" в Rect:
- компонент должен зависеть только от props
- не мутировать props, state, объекты из буков
- не вызывать fetch, setTimeout, console.log на уровне рендера
- все побочные эффекты выносить в useEeffect
- для вычислений использовать useMemo/useCallback
- стараться избегать глобальных переменных и localStorage внутри компонента


Библиотека компонентов - это набор переиспользуемых, изолированных, задокументированных UI-элементов, выполненных в едином стиле

Storybook - это отдельное приложение, которое:
- рендерит компоненты вне основного проекта
- позволяет смотреть все состояния компонента
- дает возможность менять props  через удобный интерфейс
- служит живой документацией

Storybook не часть Reacy.Это самостоятельный инструмент, которы просто берет React-код и рендерит его в изолированной среде.

Story - это одно конкретное состояние компонента, задокументированное в коде.
- позволяет показать все важные варианта использования
- сделать документацию полной и актуальной
- позволяет увидеть поведение без запуска приложения
- упрощает ревью и онбординг новых разработчиков

Каждая story - это отдельный рендер.

Args - это пропсы, которые Storybook передает компоненту и которыми можно управлять через интерфейс.
argTypes - это инструкция, какой контрол показывать.
argTypes в Storybook — это объект в метаданных компонента (meta), который описывает, как Storybook должен отображать и управлять пропсами (props) компонента в панели Controls (справа в интерфейсе).
argTypes говорит Storybook:
- какой тип данных у пропса
- какой интерфейс управления показать в панели Controls
- какие варианты значения предлагать
- как документировать пропс (описание таблица в Docs и т. д.)

Без argTypes Storybook пытается сам угадать контрол по начальному значению из args или по типу из TS, но угадывается не всегда идеально.

Control - это самая важная часть, определяющая, какой элемент управления появится в панели Controls.

CSS Modules

- безопасные имена классов
- стили лежат рядом с компонентами
- удалили компонент -> удалили стили

Интерактивная story - это история, где внутри используется useState, useEffect и другие руки.
